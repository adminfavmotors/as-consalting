# Cookiebot + Google Analytics 4

## Состояние

Интеграция подготовлена в ветке `privacy-policy`. Согласиями управляет **Cookiebot by Usercentrics**; собственный баннер и собственное хранилище согласий не создаются. Локальный адаптер связывает согласие Cookiebot с загрузкой GA4.

Без настроек ниже никакие запросы к Cookiebot или Google не выполняются. Существующие локальные шрифты, изображения и конструктор письма работают самостоятельно. Настройка аккаунтов и браузерная проверка живого баннера ещё не выполнены.

## 1. Cookiebot

Создать аккаунт клиента в [Cookiebot](https://www.cookiebot.com/en/), добавить окончательный домен и получить **Domain Group ID** в разделе скриптов. Скопировать только UUID; готовый скрипт повторно в сайт не вставлять.

Настроить:

- Польский язык, явное согласие (opt-in), запрет необязательных cookies по умолчанию для всех посетителей.
- На первом экране доступны принятие, отказ и настройка категорий; отказ столь же заметен и прост, как принятие. Не считать прокрутку/закрытие согласием и не включать статистику заранее.
- Категории: необходимые и статистические. Не добавлять рекламные сервисы. Код никогда не предоставляет рекламные сигналы Google, даже если в универсальном баннере остаётся категория Marketing.
- Ссылки на `/polityka-prywatnosci/` и `/cookies/` на окончательном домене.
- Не включать cross-domain consent sharing и географическое автоматическое согласие. Адаптер принимает только `hasResponse=true`, `consent.method=explicit`, `consent.statistics=true`.
- Выполнить сканирование, проверить классификацию `_ga` и `_ga_…` как статистических и содержимое автоматически публикуемой декларации cookies.
- Оформить необходимые условия обработки данных с поставщиком, уточнить срок хранения подтверждений согласия и обновить проект политики. Не утверждать, что длительность cookie равна длительности хранения серверного журнала согласий.

Используется документированный европейский адрес загрузки `consent.cookiebot.eu`. Режим блокировки — **manual**: единственный необязательный тег (GA4) создаётся нашим адаптером только после согласия. Встроенный писатель Google Consent Mode у Cookiebot отключён атрибутом `data-consentmode="disabled"`, поскольку согласия Google обновляет адаптер. Нельзя параллельно вставлять GTM, ещё один Google tag или второй скрипт Consent Mode. Новые трекеры требуют отдельной интеграции с согласием.

Тариф не приобретён. По текущей [странице тарифов](https://www.cookiebot.com/en/pricing/) есть бесплатный вариант для одного домена до 50 подстраниц с ограниченными возможностями; окончательная доступность зависит от сканирования и выбранных функций. Preview-поддомены могут потребовать отдельной регистрации/тарифа. Не рассчитывать на одинаковое оформление после окончания trial без проверки своего плана.

## 2. Google Analytics

В аккаунте клиента создать ресурс **GA4**, добавить веб-поток для основного домена и скопировать **Measurement ID** вида `G-…`.

Перед активацией:

- Выключить **Enhanced measurement / Pomiar zaawansowany целиком**, включая form interactions, site search, outbound clicks и history-based page views. Адаптер отправляет один явный `page_view` на HTML-страницу; Google может дополнительно создавать стандартные события сессии/вовлечённости.
- Не включать Google signals, сбор предоставленных пользователем данных, Google Ads links, ремаркетинг и рекламную персонализацию. Два соответствующих сигнала персонализации также выключены в коде.
- Проверить отсутствие connected tags, других установок GA/GTM и автоматических тегов через сторонние сервисы.
- Установить согласованный срок хранения событий; предлагаемый минимальный вариант — **2 месяца**, с выключенным сбросом срока при новом действии. Это нужно сделать в GA4: код сайта не меняет настройки аккаунта. У агрегированных отчётов и cookies отдельные правила; нельзя обещать удаление вообще всех данных через 2 месяца.
- Уточнить юридическое лицо Google в договоре, условия обработки/передачи данных, параметры обмена данными и внести подтверждённые сведения в политику.

Код удаляет query string и fragment из передаваемых `page_location` и `page_referrer`. Данные полей формы не читаются адаптером. Не помещать персональные данные в пути страниц или их заголовки. Не включать дополнительный сбор полей форм в аккаунте Google.

## 3. Vercel

В **Project → Settings → Environment Variables** задать все три значения одновременно:

| Переменная | Значение |
| --- | --- |
| `COOKIEBOT_DOMAIN_GROUP_ID` | UUID доменной группы Cookiebot |
| `GA_MEASUREMENT_ID` | ID веб-потока GA4, начинается с `G-` |
| `ANALYTICS_HOSTNAME` | Точный основной hostname, например `www.sadowski-consulting.pl`, без `https://`, пути и порта |

Это публичные идентификаторы, которые попадут в HTML. Пароли, API-ключи и доступ к аккаунтам не нужны для сборки и не должны попадать в эти поля.

Установить значения для нужного окружения и выполнить новую сборку (Redeploy). Автоматической загрузки `.env` скриптами нет; файл `.env.example` — памятка. При частичной/ошибочной конфигурации сборка завершается ошибкой, при отсутствии всех значений интеграция выключена.

Адаптер запускается только по HTTPS и только на `ANALYTICS_HOSTNAME`. Адреса с `www` и без `www` различаются: назначить один основным, второй перенаправлять на него. Это исключает попадание обычных Vercel preview в production-статистику.

Для тестирования настроить стабильный preview-hostname, зарегистрированный в Cookiebot, и отдельный тестовый ресурс GA4. Не подставлять production-hostname в `ANALYTICS_HOSTNAME` и ожидать аналитики на другом preview-адресе. Провайдерские кнопки/скрипты работают только на зарегистрированных доменах.

## 4. Проверка перед слиянием в main

`npm run build` и `npm run check` проверяют 12 страниц и автоматические сценарии согласия. Тесты наблюдают за командами и загрузкой тегов в локальном имитаторе браузера: они не выполняют код Cookiebot/Google и не доказывают, что аккаунты настроены правильно.

На настоящем preview проверить в чистом браузере:

1. До выбора и после отказа нет запросов `gtag/js`, `g/collect` или других запросов аналитики Google; `_ga` и `_ga_…` отсутствуют. Запросы самой CMP для получения/сохранения согласия ожидаемы.
2. После разрешения статистики загружается один тег GA4, появляется один `page_view`, consent `analytics_storage=granted`, все три рекламных параметра остаются `denied`.
3. Повторное открытие страницы восстанавливает выбор; кнопка **Ustawienia cookies** в подвале открывает Cookiebot.
4. После отзыва статистики прекращаются новые измерения, доступные GA cookies удаляются. Уже отправленные запросы/данные нельзя отозвать из браузера. Перезагрузка сохраняет отказ.
5. Если Cookiebot недоступен/заблокирован, GA4 не запускается. Контакт, меню и страницы продолжают работать. Ссылка настроек ведёт к пояснению, а не показывает ложное успешное сохранение.
6. Проверить польский баннер на телефоне и с клавиатурой: фокус, закрытие, отказ, настройки, доступность ссылок. В GA4 Realtime/DebugView проверить адреса и отсутствие персональных данных.
7. Проверить декларацию Cookiebot после реального сканирования, сроки cookies и отсутствие неклассифицированных trackers. Конфигурация GA cookies: максимум 365 дней, `cookie_update=false`, путь `/`, домен текущего hostname.

После подтверждения настроек обновить проект политики по `docs/PRIVACY-REVIEW.md`, убрать пометку проекта и только затем слить изменения в `main` для production. В этой задаче production не обновляется, аккаунты не создаются и подписки не покупаются.
